# ADR-011: Schema gate fail-closed with governed override (reversing 宁漏勿误)

**Status**: Accepted (implemented as specified, 2026-10-11, task C4 `10-11-schema-gate-fail-closed`; contracts pinned in `.trellis/spec/backend/governance-contracts.md` → "Release schema gate fail-closed + governed override"). Implementation notes / minor additive deviations, recorded as delivered: (1) the override table carries `revoked`/`revoked_at`/`revoked_by` in addition to the Decision-3 column sketch — the carrier of the UI's REVOKED display state (design §7 lists 已撤回); (2) override service placed in `web/component/governance` (both gate owners consume it; implement.md Step 3 discretion); (3) grant/revoke HIGH audit uses the 10-arg `logAndAddOperationAudit` overload with `ResourceType.PURE_URL` + explicit resourceName (no release-table `getResourceName` case exists; the 4-point ResourceType registration was deliberately not expanded); (4) all three endpoints (grant/list/revoke) are label-gated per R5's literal wording — the frontend override UI is gated on the same label. Functional regression on a real release (gate hits + override operation) is deferred to the project-final unified integration test per the 2026-10-11 user ruling.

**Date**: 2026-10-11

## Context

The production release schema gate (pre-A snapshot diff + pre-B structural precheck) currently runs under an explicit **fail-open design principle** — `PrecheckConclusion`: "宁漏勿误 — when in doubt, WARN_SKIP, never BLOCK". Verification against HEAD=b1915462 (evidence: Trellis `10-11-db-platform-p0-security-hardening/research/p0-gap-verification.md` §A1, design inputs in `research/adr-a-schema-gate-input.md`) confirmed:

- All three dispatch gates (`startExecution`, `retryReleaseStmt`, `handleReleaseJobCompletion`) let WARN_SKIP proceed after recording a write-only event — no permission, no reason, no expiry, no case-level audit;
- WARN_SKIP covers *inability to prove safety* (missing snapshot, unparsable SQL, DS config fetch failure, live-schema fetch failure, engine catch-all) — indistinguishable in outcome from *proven safe*; five additional silent fail-open paths (S1–S5: UNKNOWN statement type, regex extraction gaps) record nothing at all;
- The only "override" is two **hidden global switches** (`govReleaseSchemaPrecheckBlock`/`govReleaseSchemaDiffBlock`) stored as a root-owned `dm_sys_user_conf` row, **not registered** in the `RootUserConfig @UserConfigDef` whitelist — editable only by direct DB writes, with no UI, no audit, no expiry; they can even downgrade a *confirmed* BLOCK;
- The internal improvement plan (`docs/governance/internal-db-platform-improvement-plan.md` §2 P0-1, §5 Phase 1.1) requires production to default fail-closed with an explicit, permissioned, time-boxed, reasoned override.

## Decision

1. **Fail-closed reversal per the 17-category classification table** (research adr-a §3):
   - **9 categories → BLOCK**: stmt/DS field missing (P1/D1), production DS absent (P2/D3), DS config fetch failure (P3), levels parse failure (P5/D4), SQL split failure or zero scripts with the *execution-identical* splitter (P6/P7), engine catch-all exceptions (P8), live-schema fetch failure (P9/D7) — "cannot prove safe" becomes "do not dispatch"; transient infrastructure failures land as stmt FAILED and recover through the existing retry gate;
   - **2 categories stay passing** with dedicated WARN events (not WARN_SKIP semantics): shared-table baseline ambiguity (D5) and ENGINE/comment-level drift (D6) — both are *previously ruled design degradations* (SchemaFingerprintUtils explicitly excludes ENGINE/comments from the fingerprint), not "unknowns";
   - **Missing snapshot (D2) forks**: new releases BLOCK (snapshots are mandatorily propagated at creation since sub-task A — a missing snapshot on a new release is a capture-chain bug); pre-A legacy releases get a one-time documented pass event;
   - **Silent fail-open surface (S1–S5) is regularized** into "UNCERTAIN → pass + event" so the reversal does not leave a "strict above board, leaking underneath" inconsistency.
2. **"Unverifiable" is not "violation"**: new event type `RELEASE_SCHEMA_GATE_UNVERIFIABLE` (additive) separates infrastructure-unknown blocks from confirmed-violation blocks (`RELEASE_SCHEMA_PRECHECK_FAILED`) — remediation owners differ (platform fixes infra + retry vs. author fixes SQL). The stmt `FAILED` status is **reused** (the retry/return recovery machinery keys on it; a new status would pierce three guards + frontend conditions); only event types and `exec_detail` wording distinguish the two.
3. **Governed override (form A)**: new table `dm_gov_schema_gate_override` (releaseId / nullable stmtId, gateType, operatorUid, **reason NOT NULL**, expireAt, consumedFlag); new role-auth label `GOV_SCHEMA_GATE_OVERRIDE` (category CAT_RDP_DB_CHANGE_GOVERN, tag=DBA, actually wired — heeding the PROD_PROMOTE/PROD_DML_DIRECT "defined but never enforced" precedent); grant/list/revoke endpoints under `@RequestAuth` + tenant check + `SecurityLevel.HIGH` operation audit (new AuditType); gates consume an unexpired-unconsumed override → downgrade to pass + `RELEASE_SCHEMA_GATE_OVERRIDE` event (reason/expiry/operator in eventData) + **single-use consumption mark** (aligned with the DML_BATCH_RESOLUTION "an unconsumed ruling re-freezes" strictness). Expiry evaluation mirrors `DmAuthResDO.isEffective()`.
4. **Hidden switches brought into the light (form C, partially)**: register `govReleaseSchemaPrecheckBlock`/`govReleaseSchemaDiffBlock` into the `RootUserConfig @UserConfigDef` whitelist so the platform-level break-glass gains the existing UI + HIGH-audit channel (`upsertUserConfigs`); direct-DB editing stops being the only path. Semantics stay global; per-release precision is the override table's job.
5. **Accepted operational friction (deliberate)**: PARTIAL_FAILED legacy releases re-run gates unconditionally on retry (`retryReleaseStmt`) and will hit the new rules — recovery = fix infrastructure, click retry once; P3/P9-class transient failures now stop at FAILED instead of passing silently. Terminal releases (DONE/REJECTED/CANCELLED/RETURNED) have zero re-entry paths and are unaffected.

### Rejected alternatives

- **Form B (override via the existing DM_PROD_RELEASE approval ticket)**: granularity/timing mismatch — approval happens in APPROVING, but most BLOCKs surface mid-EXECUTING (chain-advance drift, infrastructure failure); post-hoc relief would require return→REVISION→resubmit (whole-release re-approval), too heavy for transient retries; the approval flow has no native expiry concept. Kept only as an optional future enhancement (second confirmation for high-risk categories).
- **Form C alone (env-param time-boxed switch as the only override)**: violates the "dedicated permission" requirement (DM_DS_MANAGE holders would gain override implicitly), no DAL-enforced reason, blast radius = the whole tenant-environment. Adopted only for its switch-registration half.
- **Keeping fail-open with alerting on WARN events**: events are write-only today and would remain advisory; the improvement plan's P0-1 explicitly requires default-deny for unprovable safety.

## Consequences

- Spec pin `governance-contracts.md` L536 ("宁漏勿误 (fail-open, never false-block)") must be revised in the C4 change; test pins flip: `ProdReleaseServiceImplTest` L839-847, `AutoExecReleaseJobCompletionTest` L704-719, diff tests L190/199/339, precheck L249 (the misleadingly named `classify_unknown_warnsSkip` asserting PASS);
- New migration (override table) follows the `AbstractUpgradeJavaMigration` precedent; new permission label requires the 3-file i18n sync (`rdp-auth-label{,_zh_CN,_en_US}.properties`);
- Frontend: override grant UI (reason modal mirroring returnStmtReason) + `myAuth.includes('GOV_SCHEMA_GATE_OVERRIDE')` button gating; new event types need `govEventConstants.js` dual-table coverage + zh/en keys;
- Verification of the reversal end-to-end (gate rejection cases per improvement plan §6 "生产门禁" row) runs in the project-final unified integration test (user ruling 2026-10-11).
